- `pre-compact.sh` — injects summary prompt before context compaction
- Registered in `.claude/settings.json`

## Plan A1 — Token-Aware Search: `compact` flag + `cortex_get_batch`

**Tier:** 1A — Optimisation
**Effort:** Small (1–2 days)
**Dependencies:** None

### Context
Cortex currently returns full memory content on every `cortex_search` call. For agents
managing large memory stores, this wastes tokens when only a few results are relevant.
Claude-Mem achieves ~10× token savings via 3-layer progressive disclosure. This plan adds
a `compact` flag to `cortex_search` and a new `cortex_get_batch` tool for two-phase retrieval.

### Files to create
- `internal/mcp/tool_get_batch.go` — new MCP tool handler
- `internal/schemas/mcp/cortex_get_batch.json` — tool JSON schema

### Files to modify
- `internal/schemas/embed.go` — add `"cortex_get_batch"` to `MCPToolNames`
- `internal/mcp/server.go` — add `"cortex_get_batch": s.handleGetBatch` to handlers map
- `internal/mcp/tool_search.go` — add `compact bool` and `include_token_estimate bool` params
- `internal/memory/service.go` — add `TokenEstimate int` field to `SearchResult` (optional output field)

### Implementation steps

**Step 1 — `SearchResult` token estimate (non-breaking)**
In `internal/memory/service.go`, add field to `SearchResult`:
```go
type SearchResult struct {
    Memory        *Memory
    Score         float64
    TokenEstimate int // approximate tokens in Content; 0 when compact=true
}
```
Populate in `service.Search()` after results are fetched:
```go
for _, r := range results {
    r.TokenEstimate = len(r.Memory.Content) / 4
}
```

**Step 2 — `compact` flag on `cortex_search`**
In `internal/mcp/tool_search.go`, extend `searchArgs`:
```go
type searchArgs struct {
    // ... existing fields ...
    Compact             bool `json:"compact"`
    IncludeTokenEstimate bool `json:"include_token_estimate"`
}
```
When `compact=true`, before marshalling results, nil out the `Content` and `Embedding`
fields on each memory copy (do not mutate originals):
```go
if a.Compact {
    for _, r := range results {
        compact := *r.Memory
        compact.Content = ""
        compact.Embedding = nil
        r = &memory.SearchResult{Memory: &compact, Score: r.Score, TokenEstimate: r.TokenEstimate}
    }
}
```
Compact result fields returned: `id`, `title`, `level`, `tags`, `score`, `token_estimate`.

**Step 3 — `cortex_get_batch` tool**
`internal/mcp/tool_get_batch.go`:
```go
type getBatchArgs struct {
    IDs []string `json:"ids"` // required
}

func (s *Server) handleGetBatch(ctx context.Context, req mcpgo.CallToolRequest) (*mcpgo.CallToolResult, error) {
    var a getBatchArgs
    if err := bindArgs(req, &a); err != nil { return toolError(...), nil }
    if len(a.IDs) == 0 { return toolError("ids is required and must not be empty"), nil }

    results := make([]*memory.Memory, 0, len(a.IDs))
    for _, id := range a.IDs {
        m, err := s.service.Get(ctx, id)
        if err != nil { continue } // skip not-found; log
        results = append(results, m)
    }
    // marshal and return
}
```
Cap at 50 IDs per call to prevent abuse (return toolError if exceeded).

**Step 4 — JSON schema** (`internal/schemas/mcp/cortex_get_batch.json`):
```json
{
  "name": "cortex_get_batch",
  "description": "Retrieve full content of multiple memories by ID. Use after cortex_search with compact:true to fetch only the relevant results.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "ids": { "type": "array", "items": { "type": "string" }, "maxItems": 50 }
    },
    "required": ["ids"]
  }
}
```

**Step 5 — Register** in `embed.go` and `server.go` (see pattern above).

### Tests
- Extend `internal/mcp/server_test.go`:
  - `TestHandleSearch_Compact_HidesContent` — assert Content is empty when compact=true
  - `TestHandleSearch_Compact_PreservesTitle` — assert Title/ID/Score present
  - `TestHandleGetBatch_ReturnsMultiple`

## Plan A2 — Timeline MCP Tool: `cortex_timeline`

**Tier:** 1A — Optimisation
**Effort:** Small (1 day)
**Dependencies:** None

### Context
Claude-Mem's `timeline` tool retrieves memories chronologically around a given observation ID.
This is valuable when debugging a sequence of events (e.g., "what did I do before and after
fixing this bug?"). Cortex has no time-window retrieval today.

### Files to create
- `internal/mcp/tool_timeline.go`
- `internal/schemas/mcp/cortex_timeline.json`

### Files to modify
- `internal/schemas/embed.go` — add `"cortex_timeline"`
- `internal/mcp/server.go` — add handler to map

### Implementation steps

**Step 1 — Handler logic**
The handler receives a `memory_id` and `window` (default 5). It:
1. Calls `s.service.Get(ctx, memoryID)` to get the anchor memory and its `SessionID` + `Level`.
2. Calls `s.service.List(ctx, ListOptions{SessionID: anchor.Context.SessionID, FilterLevels: []MemoryLevel{anchor.Level}})` to get all memories in the same session+level scope.
3. Sorts the resulting slice by `CreatedAt` ascending (in-memory sort).
4. Finds the anchor's position in the sorted slice.
5. Returns `window` entries before + `window` entries after the anchor (inclusive of anchor).

For non-working memories (no session ID), skip the session filter and list by level only,
sorting by CreatedAt across all.

```go
type timelineArgs struct {
    MemoryID string `json:"memory_id"` // required
    Window   int    `json:"window"`    // default 5; entries before + after anchor
    Level    string `json:"level"`     // optional override
}
```

**Step 2 — Sort helper**
Add a file-local sort: `sort.Slice(list, func(i, j int) bool { return list[i].CreatedAt.Before(list[j].CreatedAt) })`.

**Step 3 — Response structure**
```json
{
  "anchor": { ...full memory... },
  "before": [ ...up to window memories... ],
  "after":  [ ...up to window memories... ]
}
```

**Step 4 — JSON schema** (`internal/schemas/mcp/cortex_timeline.json`):
```json
{
  "name": "cortex_timeline",
  "description": "Retrieve memories chronologically around a given memory ID. Useful for understanding the sequence of events around a decision or bug fix.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "memory_id": { "type": "string" },
      "window": { "type": "integer", "default": 5, "minimum": 1, "maximum": 20 }
    },
    "required": ["memory_id"]
  }
}
```

### Tests
- `TestHandleTimeline_ReturnsBeforeAndAfter`
- `TestHandleTimeline_AnchorAtStart` — before slice empty
- `TestHandleTimeline_AnchorAtEnd` — after slice empty
- `TestHandleTimeline_MissingID`
- `TestHandleTimeline_SortedByCreatedAt`

### Verification
```bash

# → before: [mem1, mem2], anchor: mem3, after: [mem4, mem5]
```

## Plan A3 — Summarisation Tool: `cortex_summarise_working`

**Tier:** 1A — Optimisation
**Effort:** Small–Medium (1–2 days)
**Dependencies:** None
**Design choice:** Thinking-prompt pattern (same as `cortex_review_session`). No active LLM
call from Cortex. The tool gathers working memories and returns a structured prompt for the
agent to synthesise and store.

### Context
At session end, an agent may have accumulated many working memories. `cortex_summarise_working`
collects them, formats them into a synthesis prompt, and returns it. The agent reads the prompt,
generates a summary, then calls `cortex_consolidate` or `cortex_create` to store it as episodic.
This is consistent with all existing thinking tools.

### Files to create
- `internal/mcp/tool_summarise_working.go`
- `internal/schemas/mcp/cortex_summarise_working.json`

### Files to modify
- `internal/schemas/embed.go` — add `"cortex_summarise_working"`
- `internal/mcp/server.go` — add handler
- `internal/config/config.go` — add `SummarisationConfig` with prompt template
- `internal/config/config.go` `DefaultConfig()` — set default prompt
- `internal/config/config.go` `bindEnvVars()` — bind `CORTEX_SUMMARISATION_PROMPT_TEMPLATE`
- `internal/config/config.go` `setDefaults()` — set default

### Implementation steps

**Step 1 — Config addition**
```go
// In Config struct:
Summarisation SummarisationConfig `mapstructure:"summarisation"`

type SummarisationConfig struct {
    PromptTemplate string `mapstructure:"prompt_template"`
}
```
Default prompt template (in `DefaultConfig()`):
```
You have {{.Count}} working memories from session {{.SessionID}}.
Synthesise the key decisions, findings, and patterns into a concise episodic memory.
Focus on: what was done, what was learned, what should be remembered.

Working memories:
{{range .Memories}}
### {{.Title}}
{{.Content}}
---
{{end}}

After reading, call cortex_consolidate or cortex_create with level=episodic to store your synthesis.
```

**Step 2 — Handler logic**
```go
type summariseWorkingArgs struct {
    SessionID string `json:"session_id"` // required
    MaxItems  int    `json:"max_items"`  // default 20
}

func (s *Server) handleSummariseWorking(ctx, req) (*result, error) {
    // 1. Validate session_id
    // 2. List working memories for session
    opts := memory.ListOptions{
        FilterLevels: []memory.MemoryLevel{memory.MemoryLevelWorking},
        SessionID:    a.SessionID,
        Limit:        max(a.MaxItems, 20),
    }
    memories, err := s.service.List(ctx, opts)

    // 3. If empty, return informative message
    if len(memories) == 0 { return toolResult("No working memories found for session"), nil }

    // 4. Render template with memories
    prompt := renderSummarisationPrompt(s.config.Summarisation.PromptTemplate, memories, a.SessionID)

    // 5. Return prompt (agent synthesises and stores)
    return toolResult(prompt), nil
}
```

Template rendering uses `text/template` standard library. No external deps.

**Step 3 — JSON schema:**
```json
{
  "name": "cortex_summarise_working",
  "description": "Returns a synthesis prompt containing all working memories for a session. Read the prompt, synthesise the key learnings, then call cortex_consolidate to store as episodic memory.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "session_id": { "type": "string" },
      "max_items": { "type": "integer", "default": 20 }
    },
    "required": ["session_id"]
  }
}
```

## Plan B1 — Privacy Tags: `<private>` Support

**Tier:** 1B — UX & Privacy
**Effort:** Small (1–2 days)
**Dependencies:** None (Gob handles new bool field as zero-value false — backward compatible)

### Context
All Cortex memories are equally visible to search. In compliance-sensitive environments,
agents need to mark memories as private so they are excluded from search by default.
Claude-Mem uses `<private>` content tags; Cortex adds a `Private` bool field and
content-tag detection.

### Files to modify
- `internal/memory/types.go` — add `Private bool` to `Memory`
- `internal/memory/service.go` — detect `<private>` tag in `Create`; add `IncludePrivate` to `SearchOptions` and `ListOptions`; filter in `Search` and `List`
- `internal/storage/gob.go` — `SearchAllLayers` and `List` respect `IncludePrivate` filter
- `internal/storage/storage.go` — no change (uses `SearchOptions`/`ListOptions` from memory package)
- `internal/mcp/tool_search.go` — add `include_private bool` param
- `internal/mcp/tool_list.go` — add `include_private bool` param
- `internal/cli/search.go` — add `--include-private` flag
- `internal/cli/list.go` — add `--include-private` flag
- `internal/cli/create.go` — add `--private` flag
- `internal/mcp/tool_create.go` — add `private bool` param
- `pkg/json/memory.go` — include `private` field in JSON marshal/unmarshal
- `pkg/markdown/` — include `private: true` in YAML frontmatter on export/import

### Implementation steps

**Step 1 — `Memory` struct**
```go
// internal/memory/types.go
type Memory struct {
    // ... existing fields ...
    Obsolete bool `json:"obsolete"`
    Private  bool `json:"private,omitempty"` // new — excluded from search by default
}
```

**Step 2 — `SearchOptions` and `ListOptions`**
```go
type SearchOptions struct {
    // ... existing ...
    IncludePrivate bool // default false; private memories excluded unless true
}

type ListOptions struct {
    // ... existing ...
    IncludePrivate bool
}
```

**Step 3 — Content-tag detection in `service.Create`**
After receiving `CreateInput`, before calling `embedder.Embed`:
```go
if strings.Contains(input.Content, "<private>") || strings.Contains(input.Content, "</private>") {
    mem.Private = true
}
```
Note: Do NOT strip the `<private>` tags from content (preserve original for audit).

**Step 4 — CLI `--private` flag in `create.go`**
```go
var createPrivate bool
createCmd.Flags().BoolVar(&createPrivate, "private", false, "Mark memory as private (excluded from search by default)")
```
In `RunE`, set `input.Private = createPrivate` (add `Private bool` to `CreateInput`).

**Step 5 — Filter in storage**
In `internal/storage/gob.go`, in both `List` and `SearchAllLayers`:
```go
if !opts.IncludePrivate && m.Private {
    continue
}
```
This mirrors the existing `!opts.IncludeObsolete && m.Obsolete` pattern exactly.

**Step 6 — Export/Import preservation**
In `pkg/json/memory.go`: `Private` already serialised via JSON tag.
In `pkg/markdown/`: add `private: true` to YAML frontmatter when `Private=true`.
In import: parse `private` frontmatter field and set on Memory.

### Tests
- `TestMemoryService_Create_PrivateTagDetected` — content with `<private>` sets Private=true
- `TestMemoryService_Create_PrivateFlagSetsField` — CreateInput.Private=true sets Memory.Private=true
- `TestGobStorage_List_ExcludesPrivateByDefault`
- `TestGobStorage_List_IncludesPrivateWhenFlagSet`
- `TestGobStorage_SearchAllLayers_ExcludesPrivateByDefault`

## Plan B2 — TUI Memory Browser (Interactive Terminal UI)

**Tier:** 1B — UX & Privacy
**Effort:** Medium (4–6 days)
**Dependencies:** None
**Framework:** Charm packages (`github.com/charmbracelet/bubbletea` + `lipgloss`/`bubbles`)

### Context
Cortex is CLI-oriented. Rather than a web UI, an interactive TUI memory browser provides a better fit
for the tool's philosophy. Using Charm (bubbletea) for structured, responsive terminal interfaces,
users can explore, search, read, delete, and privatise memories without leaving the terminal.

### Files to create
- `internal/tui/browser.go` — Bubbletea application model for memory browser
- `internal/tui/list_view.go` — Memory list view component (table with sorting/filtering)
- `internal/tui/detail_view.go` — Memory detail view (full content, metadata)
- `internal/tui/search_view.go` — Search input + results (async search)
- `internal/cli/browse.go` — new `cortex browse` CLI command

### Files to modify
- `go.mod` — add `github.com/charmbracelet/bubbletea`, `github.com/charmbracelet/lipgloss`, `github.com/charmbracelet/bubbles`
- `internal/cli/root.go` — register `browseCmd`

### Implementation steps

**Step 1 — Model structure (Bubbletea)**
```go
// internal/tui/browser.go
type BrowserModel struct {
    service   *memory.MemoryService
    state     State // list | detail | search
    memories  []*memory.Memory
    cursor    int
    selected  *memory.Memory
    selection map[string]bool // multi-select: ID → true if selected
    query     string
    err       error
}

type State string
const (
    StateList   State = "list"
    StateDetail State = "detail"
    StateSearch State = "search"
)

func (m BrowserModel) Init() tea.Cmd {
    // Load initial memory list
    return loadMemoriesCmd(m.service)
}

func (m BrowserModel) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.KeyMsg:
        return m.handleKeyPress(msg)
    case loadMemoriesResult:
        m.memories = msg.memories
        return m, nil
    case searchResult:
        m.memories = msg.results
        return m, nil
    }
    return m, nil
}

func (m BrowserModel) View() string {
    switch m.state {
    case StateList:
        return m.renderListView()
    case StateDetail:
        return m.renderDetailView()
    case StateSearch:
        return m.renderSearchView()
    }
    return ""
}
```

**Step 2 — List view (scrollable table)**
```go
// internal/tui/list_view.go
func (m BrowserModel) renderListView() string {
    var rows [][]string
    for i, mem := range m.memories {
        prefix := " "
        if i == m.cursor { prefix = ">" }
        rows = append(rows, []string{
            prefix,
            truncate(mem.ID, 8),
            mem.Level,
            truncate(mem.Title, 40),
            mem.UpdatedAt.Format("2006-01-02"),
        })
    }

    s := lipgloss.NewStyle().
        Padding(1).
        Border(lipgloss.RoundedBorder())

    // Format as table using lipgloss
    return s.Render(renderTable(rows))
}

func (m BrowserModel) handleKeyPress(msg tea.KeyMsg) (BrowserModel, tea.Cmd) {
    switch msg.String() {
    case "q":
        return m, tea.Quit
    case "down":
        m.cursor++
        return m, nil
    case "up":
        m.cursor--
        return m, nil
    case "enter":
        if m.cursor < len(m.memories) {
            m.selected = m.memories[m.cursor]
            m.state = StateDetail
        }
        return m, nil
    case "/":
        m.state = StateSearch
        return m, nil
    case " ": // space — toggle selection
        if m.cursor < len(m.memories) {
            id := m.memories[m.cursor].ID
            m.selection[id] = !m.selection[id]
        }
        return m, nil
    case "d": // delete selected or all selected if multi-select
        // async delete cmd
        return m, nil
    case "p": // toggle private flag
        if m.cursor < len(m.memories) {
            // async update cmd
        }
        return m, nil
    case "o": // toggle obsolete flag
        if m.cursor < len(m.memories) {
            // async update cmd
        }
        return m, nil
    case "e": // export to markdown
        // async export cmd
        return m, nil
    }
    return m, nil
}
```

**Step 3 — Detail view (full memory content)**
```go
// internal/tui/detail_view.go
func (m BrowserModel) renderDetailView() string {
    if m.selected == nil { return "" }

    lines := []string{
        fmt.Sprintf("ID: %s", m.selected.ID),
        fmt.Sprintf("Level: %s", m.selected.Level),
        fmt.Sprintf("Title: %s", m.selected.Title),
        fmt.Sprintf("Private: %v", m.selected.Private),
        fmt.Sprintf("Obsolete: %v", m.selected.Obsolete),
        "",
        m.selected.Content,
        "",
        "Press 'b' to go back, 'd' to delete, 'p' to toggle private, 'o' to toggle obsolete, 'e' to export",
    }

    return lipgloss.NewStyle().
        Padding(1).
        Render(strings.Join(lines, "\n"))
}
```

**Step 4 — Search view (async search)**
```go
// internal/tui/search_view.go
type searchResultMsg struct {
    results []*memory.Memory
    err     error
}

func searchMemoriesCmd(svc *memory.MemoryService, query string) tea.Cmd {
    return func() tea.Msg {
        results, err := svc.Search(context.Background(), query, memory.SearchOptions{TopK: 20})
        if err != nil {
            return searchResultMsg{err: err}
        }
        // Convert SearchResult to Memory slice
        var mems []*memory.Memory
        for _, r := range results {
            mems = append(mems, r.Memory)
        }
        return searchResultMsg{results: mems}
    }
}
```

**Step 5 — CLI command**
```go
// internal/cli/browse.go
var browseCmd = &cobra.Command{
    Use:   "browse",
    Short: "Interactive terminal UI for browsing memories",
    Long:  "Opens an interactive TUI to list, search, view, and manage memories.",
    RunE: func(cmd *cobra.Command, args []string) error {
        store, err := initStorage()
        if err != nil { return err }
        embedder, err := initEmbedder()
        if err != nil { return err }

        svc := memory.NewMemoryService(store, embedder)
        m := tui.New(svc)
        p := tea.NewProgram(m, tea.WithAltScreen())
        _, err = p.Run()
        return err
    },
}
```

- `o` — toggle obsolete flag on selected memory
- `e` — export selected memory or memories to markdown
- `q` — quit

## Plan C1 — SQLite Backend + FTS5 Hybrid Search

**Tier:** 2 — Core Parity
**Effort:** Large (7–10 days)
**Dependencies:** None (GobStorage stays default)
**Library:** `modernc.org/sqlite` (pure Go, no CGo, recommended in roadmap)

### Context
GobStorage has no full-text index — searching for exact terms like function names or error codes
relies on semantic similarity alone. This plan adds a SQLite-backed storage implementation with
FTS5 support and hybrid cosine + BM25 ranking, accessible via `storage.backend: sqlite` config.
A migration CLI command imports existing Gob memories into SQLite.

### Files to create
- `internal/storage/sqlite.go` — `SQLiteStorage` implementing `storage.Storage`
- `internal/storage/sqlite_test.go`
- `internal/cli/migrate.go` — `cortex migrate --to sqlite [--dry-run]` CLI command

### Files to modify
- `go.mod` — add `modernc.org/sqlite`
- `internal/storage/storage.go` — add `New(cfg StorageConfig) (Storage, error)` factory (if not exists)
- `internal/config/config.go` — validate `storage.backend: sqlite` in `StorageConfig`
- `internal/cli/root.go` — register `migrateCmd`
- `docs/analysis/designs/sqlite-backend.md` — design document (created by this plan)

### Implementation steps

**Step 1 — SQLite schema**
```sql
CREATE TABLE IF NOT EXISTS memories (
    id          TEXT PRIMARY KEY,
    level       TEXT NOT NULL,
    title       TEXT NOT NULL,
    content     TEXT NOT NULL,
    tags        TEXT,               -- JSON array
    embedding   BLOB,               -- gob-encoded []float64
    context     TEXT,               -- JSON object
    created_at  DATETIME NOT NULL,
    updated_at  DATETIME NOT NULL,
    merged_from TEXT,               -- JSON array
    obsolete    INTEGER NOT NULL DEFAULT 0,
    private     INTEGER NOT NULL DEFAULT 0,
    session_id  TEXT                -- denormalised from context for query performance
);

CREATE VIRTUAL TABLE IF NOT EXISTS memories_fts USING fts5(
    id UNINDEXED,
    title,
    content,
    content='memories',
    content_rowid='rowid'
);

CREATE INDEX IF NOT EXISTS idx_memories_level ON memories(level);
CREATE INDEX IF NOT EXISTS idx_memories_session ON memories(session_id);
CREATE INDEX IF NOT EXISTS idx_memories_obsolete ON memories(obsolete);
```
FTS5 uses a content table (not a shadow copy) — triggers keep it in sync:
```sql
CREATE TRIGGER memories_ai AFTER INSERT ON memories BEGIN
  INSERT INTO memories_fts(rowid, id, title, content) VALUES (new.rowid, new.id, new.title, new.content);
END;
CREATE TRIGGER memories_ad AFTER DELETE ON memories BEGIN
  INSERT INTO memories_fts(memories_fts, rowid, id, title, content) VALUES ('delete', old.rowid, old.id, old.title, old.content);
END;
CREATE TRIGGER memories_au AFTER UPDATE ON memories BEGIN
  INSERT INTO memories_fts(memories_fts, rowid, id, title, content) VALUES ('delete', old.rowid, old.id, old.title, old.content);
  INSERT INTO memories_fts(rowid, id, title, content) VALUES (new.rowid, new.id, new.title, new.content);
END;
```

**Step 2 — `SQLiteStorage` struct**
```go
type SQLiteStorage struct {
    db   *sql.DB
    path string
    mu   sync.RWMutex // guards write operations
}

func NewSQLiteStorage(path string) (*SQLiteStorage, error)
```

**Step 3 — Hybrid `SearchAllLayers`**
Two parallel searches merged:
1. Semantic: load all embeddings from DB, compute cosine similarity in-memory (same as Gob)
2. FTS5: `SELECT id, bm25(memories_fts) AS rank FROM memories_fts WHERE memories_fts MATCH ? ORDER BY rank`
Merge: `hybrid_score = 0.6 * cosine_norm + 0.4 * bm25_norm` (configurable weights via config).
Dedup by ID, sort by hybrid_score, take TopK.

Alpha weight configurable:
```go
type SearchConfig struct {
    // ... existing ...
    HybridSemanticWeight float64 `mapstructure:"hybrid_semantic_weight"` // default 0.6
}
```

**Step 4 — `cortex migrate` command**
```go
var migrateCmd = &cobra.Command{
    Use:   "migrate",
    Short: "Migrate storage backends",
}
var migrateToSQLiteCmd = &cobra.Command{
    Use:  "to-sqlite",
    RunE: func(cmd *cobra.Command, args []string) error {
        // 1. Open GobStorage (source)
        // 2. Open SQLiteStorage (dest)
        // 3. List ALL memories from Gob (include obsolete, include private)
        // 4. For each memory: dest.Save(ctx, m)
        // 5. Report count
    },
}
```
Dry-run flag: `--dry-run` — lists what would be migrated without writing.

**Step 5 — Config backend selection**
In `internal/config/config.go`:
```go
type StorageConfig struct {
    Backend string `mapstructure:"backend"` // "gob" (default) | "sqlite"
    Path    string `mapstructure:"path"`
}
```
In `internal/storage/storage.go` factory:
```go
func New(cfg config.StorageConfig) (Storage, error) {
    switch cfg.Backend {
    case "sqlite":
        return NewSQLiteStorage(cfg.Path)
    default:
        return NewGobStorage(cfg.Path)
    }
}
```

## Plan C2 — IDE Lifecycle Integration (Claude Code Hooks)

**Tier:** 2 — Core Parity
**Effort:** Medium (3–5 days)
**Dependencies:** None (extends existing hook system)
**Scope:** Improve existing session-start/session-stop hooks + add UserPromptSubmit hook

### Context
The existing `cortex hooks init` generates session-start.sh, session-stop.sh, and pre-compact.sh.
This plan improves the existing hooks (better context injection, more reliable transfer) and adds
a new `UserPromptSubmit` hook that searches Cortex for context relevant to each incoming prompt —
the key missing capability vs Claude-Mem.

### Files to modify
- `internal/cli/hooks.go` — extend `initHooksCmd` to generate improved scripts + new UserPromptSubmit
- `.claude/settings.json` (generated by the command) — add `UserPromptSubmit` entry
- Template strings for all hook scripts (inline in hooks.go or in `internal/templates/hooks/`)

### Implementation steps

**Step 1 — Improved `session-start.sh`**
Current: lists working memories.
Improved:
1. Derives session ID from git branch (already done).
2. Runs `cortex list --level working --session "$SESSION_ID" --json` — structured JSON, not plain text.
3. Runs `cortex list --level semantic --limit 5 --json` — top semantic memories as standing context.
4. Emits a well-formatted context block:
```
=== Cortex Memory Context ===
Session: $SESSION_ID (branch: $BRANCH)

Working memories (this session): N items
[structured list]

Core conventions (semantic): N items
[structured list]
===
```
Output goes to stdout → injected as Claude Code session context.

**Step 2 — Improved `session-stop.sh`**
Current: one-shot review that blocks the stop and re-injects a prompt.
Improved:
1. Keep one-shot pattern (block + review prompt on 1st call).
2. On 1st call: additionally call `cortex transfer-working --session "$SESSION_ID" --json` to ensure transfer happens even if agent forgets.
3. Add check: if no working memories exist, skip the review step silently.
4. Daily autoprune remains unchanged.

**Step 3 — New `UserPromptSubmit` hook**
This is the key addition. Claude Code fires this hook with the user's prompt text as input.
The hook extracts relevant context and appends it to a context file.

Script: `user-prompt-submit.sh`
```bash
#!/bin/bash
# UserPromptSubmit hook: inject relevant Cortex context before each prompt

PROMPT="$CLAUDE_USER_PROMPT"         # Claude Code provides this env var
SESSION_ID=$(cortex session id 2>/dev/null)

# Quick semantic search based on the user's prompt (top 3 results, compact)
RESULTS=$(cortex search "$PROMPT" --top 3 --min-score 0.55 --json --compact 2>/dev/null)

if [ -n "$RESULTS" ] && [ "$RESULTS" != "[]" ]; then
    echo ""
    echo "<!-- cortex: relevant memories -->"
    echo "$RESULTS"
    echo "<!-- /cortex -->"
fi
```

Note: `--compact` flag (Plan A1) is required here to keep token overhead minimal.
The hook must be fast (< 500 ms); if `cortex search` is slow (Ollama cold), the hook
should timeout gracefully and emit nothing rather than blocking.

Add timeout wrapper: `timeout 3s cortex search ...` — if it fails, emit nothing.

**Step 4 — `settings.json` update**
The generated `.claude/settings.json` must register the new hook:
```json
{
  "hooks": {
    "SessionStart": [{ "type": "command", "command": ".claude/hooks/session-start.sh" }],
    "UserPromptSubmit": [{ "type": "command", "command": ".claude/hooks/user-prompt-submit.sh" }],
    "Stop": [{ "type": "command", "command": ".claude/hooks/session-stop.sh" }],
    "PreCompact": [{ "type": "command", "command": ".claude/hooks/pre-compact.sh" }]
  }
}
```

**Step 5 — Idempotency**
`cortex hooks install-claude-code` (or an improved `cortex hooks init`):
- If scripts already exist, overwrite with updated versions (with `--force` flag for safety).
- Merge `settings.json` entries rather than overwriting (preserve user's existing hooks).

### Tests
- `TestHooksInit_GeneratesAllFourScripts`
- `TestHooksInit_IsIdempotent`
- `TestUserPromptSubmitScript_OutputsContextWhenResultsFound` (bash unit test via `bats` or Go exec test)
- `TestSessionStartScript_OutputsStructuredContext`
- `TestSettingsJSON_ContainsAllHookTypes`

### Verification
```bash

# → Type a prompt: hook fires, relevant memories appear before response
```

## Plan D1 — Storage Migration & Performance

**Tier:** 3 — Infrastructure
**Effort:** Large (5–8 days)
**Dependencies:** Plan C1 (SQLite backend) must be completed first

### Context
GobStorage's in-memory cosine search is O(N·D). Beyond ~10k memories this becomes
measurable. This plan benchmarks both backends and introduces GobStorage lazy index loading
to reduce startup time for large datasets.

### Scope
1. Benchmark suite: GobStorage vs SQLiteStorage at 1k / 10k / 50k / 100k memories.
2. Lazy index loading for GobStorage: defer full vector index build to first search.
3. Evaluate HNSW feasibility (document recommendation, don't implement unless benchmarks show clear need).

### Files to create
- `internal/storage/bench_test.go` — benchmark suite (uses `testing.B`)
- `docs/analysis/designs/storage-performance.md` — benchmark results + HNSW recommendation

### Files to modify
- `internal/storage/gob.go` — lazy vector index: build on first `SearchAllLayers` call, not on `load()`

### Implementation steps

**Step 1 — Benchmark setup**
```go
func BenchmarkGobStorage_Search_1k(b *testing.B) { benchmarkSearch(b, "gob", 1000) }
func BenchmarkGobStorage_Search_10k(b *testing.B) { benchmarkSearch(b, "gob", 10000) }
func BenchmarkSQLiteStorage_Search_1k(b *testing.B) { benchmarkSearch(b, "sqlite", 1000) }
// ...
```
Helper generates synthetic memories with random embeddings.

**Step 2 — Lazy GobStorage index**
Add `indexBuilt bool` field. In `SearchAllLayers`, check `if !s.indexBuilt { s.buildVectorIndex(); s.indexBuilt = true }`.
This avoids rebuilding the index on every `Save` operation for large stores.

**Step 3 — Document HNSW threshold**
Based on benchmarks, add recommendation to `docs/analysis/designs/storage-performance.md`:
- < 10k: GobStorage adequate
- 10k–100k: SQLiteStorage with current linear cosine scan adequate
- > 100k: HNSW recommended (suggested lib: `github.com/coder/hnsw`)

### Verification
```bash
go test ./internal/storage/... -bench=. -benchmem -count=3
# Compare ns/op across 1k / 10k / 50k
```

## Plan D2 — Multi-Project Memory

**Tier:** 3 — Infrastructure
**Effort:** Medium (3–4 days)
**Dependencies:** None (works with both Gob and SQLite)

### Context
Claude-Mem scopes memories to a `project` field automatically. Cortex stores everything in one
path. This plan adds automatic project detection from git remote URL, creating per-project
namespaces, and a `--all-projects` cross-project search flag.

### Files to create
- `pkg/project/project.go` — project ID derivation (hash of git remote URL)

### Files to modify
- `internal/config/config.go` — add `ProjectConfig{AutoDetect bool, ID string}`

- `internal/memory/service.go` — filter by project in `List` and `SearchAllLayers` by default
- `internal/cli/search.go` — add `--all-projects` flag
- `internal/storage/gob.go` — respect ProjectID filter in List/Search
