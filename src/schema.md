# Cortex schema: the second brain

You maintain this personal wiki. The human chooses the sources, asks the questions and sets the direction. You do the bookkeeping: summarize, link, update, flag contradictions. This file is authoritative. Suggest a change when a convention no longer holds.

> Generated by `cortex` from its built-in schema (or the file named by `schema` in `cortex.json`). Regenerate it with `cortex schema --write` rather than editing it by hand.

## Absolute rules

1. **`raw/` is immutable.** You read it, you never modify it. Single exception: switching a source's `status` field from `pending` to `compiled`.
2. **You only write inside `wiki/`.** A new source enters `raw/` through `cortex add`, never by hand.
3. **Every factual claim is sourced** with a footnote `[^id]`, where `id` matches an entry of `sources[]`. When you have no source, say so explicitly ("to be checked").
4. **You never write `wiki/index.md` or `wiki/log.md` by hand**: `cortex index` regenerates the first from the frontmatters, and `cortex log add` appends to the journal (`wiki/log.jsonl`), from which `log.md` is generated.
5. **You update before you create.** Look for an existing page first (index, then search). A duplicate is worth less than an enriched page.
6. **You keep the human in the loop.** On every ingest, present what you keep and the pages you intend to touch, then write.
7. Wiki language: **{{language}}**. Quotes and source titles stay in their original language.

## Layout

```
cortex.json                  # configuration; marks the wiki root
raw/YYYY/MM/<uuid>/source.md # extracted sources (+ assets/); default naming
wiki/index.md                # catalog (OKF reserved, no frontmatter)
wiki/log.jsonl               # append-only journal, source of truth (one JSON entry per line)
wiki/log.md                  # generated from log.jsonl (OKF reserved)
wiki/sources/<uuid>.md       # type: Source: one per raw source
wiki/concepts/<uuid>.md      # type: Concept: an idea
wiki/entities/<uuid>.md      # type: Entity: a person, tool, project or organization
wiki/syntheses/<uuid>.md     # type: Synthesis: a stored answer, comparison or thesis
```

- **Identifiers: UUID v7 by default**, for raw sources and wiki pages alike (time-ordered then random: unique, no name collision, sorted in creation order). Naming and folder structure are set in `cortex.json` (`raw_path`, `page_path`); the layout above is the default one. You never make up a name: `cortex add` names a source, `cortex new` creates a page, following the configuration. You find a page by its **title** (index, `cortex search`), not by its file name.
- **A name is final.** A page is never renamed: change its title, its path stays.

## Raw source format (`raw/.../source.md`)

```yaml
---
type: RawSource
title: "Original title"
url: https://…                # absent for a personal note
kind: article                 # article | pdf | video | audio | image | note | repo | thread
sha256: …                     # filled in by the CLI
blob: .cortex/blobs/…         # optional binary original, outside git
fetched_at: 2026-11-04T09:12:00+01:00
extractor: manual             # or cortex-cli/0.1+readability, yt-dlp+whisper…
note: "Why I keep this"       # MANDATORY: the human's intent
status: pending               # pending | compiled | skipped
---
<extracted content, in Markdown>
```

If the `note` field is missing, ask the human for it before compiling.

## Wiki page format (OKF v0.2 subset)

```yaml
---
type: Concept                       # Source | Concept | Entity | Synthesis (the only mandatory field)
title: Context rot
description: One sentence, used as is in the index.
tags: [llm, context-engineering]    # 1 to 4, lowercase, reuse rather than invent
status: draft                       # draft | stable | deprecated
generated: { by: claude-code/opus-5.5, at: 2026-11-04T10:00:00+01:00 }
sources:
  - id: chroma-context-rot
    resource: /raw/2026/11/01a1a5c9-5e80-7075-ae13-aab03b0a8697/source.md
    title: "Context Rot (Chroma Research)"
# verified: { by: "human:<name>", at: … }   ← added only once the human has reviewed the page
# stale_after: 2027-06-01T00:00:00+00:00    ← for perishable topics (versions, prices)
---
Prose body. A claim.[^chroma-context-rot] See [Context engineering](/wiki/concepts/01a1a5d1-2b40-7d10-8a77-c03f19e2b5a4.md).

[^chroma-context-rot]: Optional detail (section, page, timestamp).
```

- **`generated.at`**: update it on every significant change. **`generated.by`** always names the actual actor.
- **Links:** root-relative Markdown links (`/wiki/…md`, the path printed by `cortex new`), with the target page's title as the link text. A link always points to an existing page. For a concept still to write, create it with `cortex new` (a `status: draft` stub is enough), then link to it.
- **Reviewed page, then modified:** keep the `verified` entry (it is a past event), but switch back to `status: draft`. A `generated.at` later than `verified.at` means the page needs another review.
- **Deprecation:** a page contradicted by a more recent source is not deleted. It switches to `status: deprecated`, with a link at the top to what replaces it.
- **`Source` page:** it holds a summary, 3 to 7 key points, the human's `note`, and links to the concepts and entities it touches.
- **The `note` is copied into a callout** at the top of the body, with Obsidian's callout syntax and nothing else:
  ```markdown
  > [!note] Note personnelle
  > <the note, verbatim>
  ```
- **A limitation of the source (partial extraction, paywall) goes into a warning callout**, separate from the note:
  ```markdown
  > [!warning]
  > Partial article because of the paywall: about 30% was extracted.
  ```

## `wiki/index.md`

This file has no frontmatter. It holds one section per type, and one bullet per page:

```markdown
# Index

## Concepts
- [Context rot](/wiki/concepts/01a1a5d1-2b40-7c3e-9f21-5d8e0a4b7c12.md) — <description>

## …
```

## `wiki/log.jsonl` and `wiki/log.md`

`wiki/log.jsonl` is the journal: one JSON entry per line, chronological order, append-only. `wiki/log.md` is **generated** from it (readable in Obsidian, OKF reserved): the most recent entries come first, grouped by date. **You never write the journal by hand**: `cortex log add`.

```json
{"at": "2026-11-04T10:00:00+01:00", "kind": "ingest", "text": "created Context rot, updated Chroma.", "sources": ["01a1a5c9-5e80-7075-ae13-aab03b0a8697"], "pages": ["wiki/concepts/01a1a5d1-2b40-7c3e-9f21-5d8e0a4b7c12.md"]}
```

- `kind`: `add` | `ingest` | `query` | `lint` | `update`. `text`: one line of inline Markdown. `sources` (raw ids) and `pages` (`wiki/….md` paths) are optional and validated: pass them rather than copying them into the text.
- `cortex log add <kind> "<text>" [--source <id>]… [--page <path>]…` writes the entry with the current time and regenerates `log.md`. Put the text in double quotes, without `$` or backticks (single quotes if the text contains some).
- `log.md` renders each entry as a bullet `- **Kind** text`, followed by the sources and pages (by title) the text does not already name:

```markdown
## 2026-11-04
- **Ingest** created Context rot, updated Chroma. (sources : `01a1a5c9-5e80-7075-ae13-aab03b0a8697`)
- **Lint** 3 orphans, 1 contradiction (Context rot vs Context engineering).
```

## INGEST workflow

1. Read the raw source in full, `note` field included. For an image, describe it with your vision. For a transcript, ignore the spoken noise.
2. Read `wiki/index.md`, then look for related pages: `cortex search "<terms>"`.
3. **Present to the human**, in 5 to 10 lines, what the source brings, what contradicts existing pages, and the list of pages to create or modify. Wait for their approval or corrections.
4. Write:
   - the Source page, created by `cortex new Source "<title>"` (the CLI prints its path, then you fill in the file);
   - the updates to existing concepts and entities, or their creation with `cortex new Concept|Entity "<title>"` when nothing comes close;
   - the links, in both directions.
5. Switch the raw source to `status: compiled`, unless you were started by `cortex compile`, which does it after checking that a Source page cites the source.
6. Run `cortex index`. Add the **Ingest** entry to the journal: `cortex log add ingest "…" --source <id> --page wiki/…md` for every page touched (the **Add** entry is already there, written by `cortex add`).

In your answer, do not copy the pages back: summarize in one line per file touched.

## QUERY workflow

1. Read `wiki/index.md`, pick the relevant pages and read them **in full**. Do not reason on excerpts.
2. If the wiki is not enough, search `raw/` (`cortex search "<terms>" --in raw`). An answer found only in `raw/` reveals a **gap**: suggest compiling that source.
3. Answer by citing the wiki pages, with their links. Tell apart what the wiki says from what you infer.
4. If the answer has lasting value (comparison, synthesis, decision), suggest storing it as a Synthesis page (`cortex new Synthesis "<title>"`), then the journal (`cortex log add query "…" --page wiki/….md`) and the index.

## LINT workflow

Run `cortex lint --json`. It reports:
- **errors** (exit code 1): invalid YAML, missing `type` or `description`, broken link, footnote without a `sources[]` entry, missing resource, duplicate raw id;
- **warnings**: orphan page, page modified since its review, `stale_after` passed, source `pending` for more than 7 days or without a `note`, compiled source that no Source page cites, likely duplicates (same title, same raw source), near-synonym tags, file name outside the configured naming;
- **info**: pages never reviewed.

What the CLI cannot see is up to you: **contradictions between pages**.

Fix what is mechanical. **Propose** to the human what needs judgment (merge, deprecate, settle a contradiction). End with a **Lint** entry in the journal (`cortex log add lint "…"`).

## The `cortex` CLI

```
cortex add <url|file|-> --note "why I keep this" [--dry-run]         # → raw/, status: pending, Add entry in the journal
cortex inbox [--dry-run]                                             # add on inbox/ (urls.txt, files), then empties it
cortex search "<terms>" [--in wiki|raw] [--json]                     # BM25, wiki first
cortex index                                                         # regenerates wiki/index.md and wiki/log.md
cortex new <Source|Concept|Entity|Synthesis> "<title>"               # creates the page (draft) per page_path, prints its path
cortex log [--limit N] [--json] [--kind k]                           # reads the journal, newest first
cortex log add <kind> "<text>" [--source <id>]… [--page <path>]…     # appends an entry to wiki/log.jsonl
cortex lint [--json]                                                 # mechanical checks
cortex compile <id…> | --pending [--batch]                           # runs an agent on INGEST
cortex ask "<question>" [--file] [--interactive]                     # runs an agent on QUERY
cortex schema [--write]                                              # prints this schema; --write rewrites the agent file
cortex config init [client] | lint | get [key] | set <key> <value> | remove <key>   # cortex.json
cortex mcp                                                           # MCP server on stdio (external agents)
cortex export [--out <dir>]                                          # the wiki as an interactive HTML site (default: .cortex/site)
```

- `cortex add` is idempotent: a URL or content already present returns the existing id.
- `cortex inbox` ingests `inbox/`: `urls.txt` (one `<url> [note…]` per line, `#` and blank lines ignored) and any other file (optional note in `<name>.note`). A successful entry (added or already present) leaves the inbox, a failure stays (exit code 1). Without a note, the source waits for its `note` as after `cortex add`.
- `partial:` flags an incomplete extraction (paywall). Say so in the Source page.
- `cortex add` refuses an HTTP error status or an almost empty body. Do not work around a paywall: ask the human for the text, then `cortex add -` with it on standard input.
- **`cortex compile`** runs one agent session **per source**, one after the other (one session per task, against context rot).
  - **By default the session is interactive**: you present your plan to the human before writing (rule 6).
  - **With `--batch`, nobody approves**: you write directly, and every page touched goes to `status: draft`, to be reviewed later.
  - The CLI refuses a source whose `note` is empty. It switches the status to `compiled` only if a Source page cites the source, then regenerates the index. It reports any file modified outside `wiki/`.
- **`cortex mcp` exposes the wiki to an external agent**: `search`, `get`, `related`, `lint`, `log` (JSON entries of the last days, `kind` filter) read-only, and `add` (URL or text, into `raw/` only, `note` mandatory). It never modifies `wiki/`: ingesting stays the job of `cortex compile`.
- **`cortex export` publishes the wiki as a static site** (navigation, instant search, link graph) with no LLM and no server. It only reads `wiki/`: `raw/` is never published, sources point to their original URL. The output directory is emptied on every export.
- **`cortex ask` is read-only.** `--file` allows storing the answer as a Synthesis page (in `draft`), with its journal entry; the index and `log.md` are then regenerated.
- **`cortex.json` picks the agent** (`{ "client": "claude" | "codex" | "opencode", "model": "…", "effort": "…" }`). `cortex config` manages it and validates every write. `effort` uses the client's vocabulary: `low`…`max` for Claude, `minimal`…`xhigh`, `max`, `ultra` or `persistent` for Codex, the name of a model variant for opencode. Model and effort apply to batch and interactive runs alike.
- **`cortex.json` also sets**:
  - `language`: the wiki language (rule 7);
  - `schema`: a Markdown file, relative to the root, that replaces the built-in schema;
  - the naming: `raw_path` (folder of a source under `raw/`, whose last segment is the raw id; default `{yyyy}/{mm}/{uuid}`) and `page_path` (path of a page under `wiki/`, without `.md`; default `{type}/{uuid}`). Placeholders: `{uuid}` `{yyyy}` `{mm}` `{dd}` `{hh}` `{mi}` `{ss}` `{slug}` `{rand}`, plus `{kind}` (raw) and `{type}` (pages). A name already taken gets `-2`, `-3`…; `cortex lint` reports what does not follow the templates.
- **Agent file:** `cortex config init` writes this schema to `CLAUDE.md` (Claude, or no client) or `AGENTS.md` (Codex, opencode); `cortex schema --write` rewrites it.
  - **Without `client`, the CLI stays agent-agnostic**: `$CORTEX_AGENT` for interactive mode (default `claude`), `$CORTEX_AGENT_BATCH` for `--batch` and `ask` (default `claude -p`, which reads the prompt on standard input). The agent runs in a sandbox (bubblewrap on Linux, `sandbox-exec` on macOS) where the whole repository is read-only except `wiki/`.
  - **With a `client`**, `--batch` and `ask` go through its SDK or API, and your writes outside `wiki/` are blocked **before** they happen. Claude: every tool call is checked (Bash limited to `cortex search|index|lint|new|log`). Codex: an OS sandbox started from `wiki/`. opencode: permission rules (`edit` limited to `wiki/*`, shell limited to `cortex`).
  - Interactive mode starts the client's CLI (`claude`, `codex`, `opencode --prompt`), unless `$CORTEX_AGENT` is set. It is confined the same way.
